## 2. AppShell auth-loop finding (root cause of F-1's silent failure)

`AppShell.tsx` does **not** react to 401s from `api()` — `lib/api.ts:29` just `throw new Error(...)` on any non-OK response, and no page or shared code catches 401 specifically. Instead, `AppShell` gates access purely via Firebase's `onAuthStateChanged` (`AppShell.tsx:119-127`):

```ts
const unsub = onAuthStateChanged(auth, (u) => {
  if (!u) { router.replace("/login"); }
  else { setUser(u); setAuthLoading(false); loadWorkspaceData(); }
});
```

Because email/password login (`login/page.tsx:74-97`) never calls Firebase — it only does `localStorage.setItem("webpilot_user", ...)` and `router.push("/app")` — `auth.currentUser` is still `null` immediately afterward. When `/app/layout.tsx` mounts `AppShell`, `onAuthStateChanged` fires synchronously with `u = null` and immediately calls `router.replace("/login")` — **before any page component or API call ever executes**. The user is bounced straight back to `/login` with no error message, no toast, nothing in the `err` state. It looks exactly like the login button did nothing.

## 8. Accessibility quick pass

- Icon-only buttons frequently lack `aria-label`, relying only on `title` (sidebar collapse toggle, schedule action icons, connection edit/delete icons).
- All ~7 custom modals are plain `<div>` overlays with no `role="dialog"`, no `aria-modal`, no focus trap, no Escape-to-close.
- `window.confirm`/`window.prompt` are at least natively accessible/keyboard-operable — a real property any replacement `ConfirmDialog` needs to preserve.
- Status conveyed via color + text (not color-only) — fine.
- Form labels are visually associated but mostly not `htmlFor`/`id`-linked, breaking click-to-focus and screen-reader announcement in several forms.
- Semantic `<nav>`/`<Link>` used correctly in the sidebar; active state via color + border.
- No skip-to-content link.
